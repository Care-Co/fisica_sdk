# BLE 측정 경로: 문서·기존 SDK·코어 대조

2026-10-13. 프로토콜 문서(`케어앤코-Fisica-Scale.pdf` 12·15·16쪽, `250310_케어앤코-Fisica-Scale.pdf`)와
공개된 1.0.1 SDK, 현재 코어를 비교했다. 실기기 확인은 하지 못했다.

## 세 가지가 서로 다르다

| | 연결 설정 (0x22) | 측정 명령 | 근거 |
|---|---|---|---|
| 프로토콜 문서 | BLE=1, USB=2 | 연속 측정(0x51)은 USB 설정에서만 가능. BLE는 단일(일반) 측정(0x50) | 문서 12쪽, 2025-03-10 보완 |
| 1.0.1 SDK (PyPI) | USB·BLE 모두 BLE(1)로 설정 | 두 연결 모두 연속 측정(0x51) | `serial_handler.py`, `bluetooth_handler.py` |
| 현재 코어 | 연결 종류에 맞게 BLE=1 / USB=2 | 두 연결 모두 연속 측정(0x51) | `native/src/fisica_session.cpp` |

문서에서 추가로 확인한 것:

- 2025-03-10 보완: 단일 측정 데이터를 BLE로 보내며, 시작 명령에서 사용자 ID 항목이 빠져 8-byte가 됐다.
  코어의 `start_single_measurement`는 이전 9-byte 형식(사용자 ID 포함)이다.
- 같은 보완: 단일·연속 측정 데이터 길이를 같게 했고 맨 앞에 측정 카운트 인덱스가 있다(연속 측정은 0 고정).
  문서 16쪽의 644 byte에 이 1 byte가 더해져 SDK가 쓰는 645 byte가 된다. 코어가 격자를 1번 바이트부터 읽는 것과 맞는다.
- 측정 횟수(0x20)와 측정 간격(0x23, 100~2000ms)은 일반 측정에 적용된다. 단일 측정이 횟수만큼 보내고
  스스로 끝나는지, 끝날 때 무엇을 보내는지는 문서에 없다.
- 오류 코드 6: 측정 제어를 설정된 연결 디바이스가 아닌 쪽에서 하면 제어 오류.

실기기 근거는 한 건뿐이다: Mac USB, `2.0.2-RC1`, USB 설정 + 연속 측정에서 ACK와 645-byte 프레임 확인
([세션 코어 검증](session-core-verification.md)). BLE 근거는 없다.

## 코어를 지금 바꾸지 않은 이유

BLE에서 연속 측정이 거절되는지, 단일 측정이 어떻게 끝나는지 모르는 상태로는 상태 머신을 정할 수 없다.
요구사항도 명령 바이트를 바꾸기 전에 문서·저장 샘플·실기기 결과를 함께 비교하도록 한다.
그래서 코어의 BLE 경로는 그대로 두고, 두 후보를 실제 기기에서 한 번에 확인하는 도구를 만들었다.

## 확인 방법

Bluetooth 권한이 있는 터미널에서, 사람이 Scale에 올라선 상태로 펌웨어별 1회 실행한다.

```sh
python tools/ble_probe.py --seconds 5 --out ble-2.0.1.json
python tools/ble_probe.py --seconds 5 --out ble-2.0.2.json
```

기록하는 것: 광고 이름, GATT 표(서비스·characteristic·속성), 기본 프로필 UUID 일치 여부, MTU,
그리고 두 시퀀스 각각의 ACK/NACK와 기기 오류 코드, 프레임 수와 간격, 카운트 인덱스 값, 종료·해제 결과.
보내는 명령은 펌웨어 조회, 연결 설정, 측정 시작·종료, 설정 해제뿐이다. 영점·보정·Wi-Fi·OTA는 보내지 않는다.

- `continuous`: 현재 코어의 BLE 시퀀스(BLE 설정 → 0x51 시작/종료 → 해제)
- `single`: 문서의 BLE 시퀀스(BLE 설정 → 0x50 시작 8-byte → 0x50 종료 → 해제)

## 결과에 따른 처리

| 결과 | 코어 변경 |
|---|---|
| BLE에서 연속 측정이 ACK되고 프레임이 온다 | 변경 없음. 문서와 다른 실제 동작으로 기록하고 프로필을 검증됨으로 표시 |
| 연속 측정은 거절, 단일 측정은 동작 | BLE 연결의 측정 경로를 0x50으로 분리. 종료 조건(횟수·종료 응답)을 기록에서 확정한 뒤 세션 상태 머신에 추가 |
| 펌웨어 버전마다 다르다 | 펌웨어 조회 결과로 경로를 고른다. 조회 실패 시의 기본 경로를 함께 정한다 |
| 둘 다 거절 | BLE 측정 미지원으로 문서화하고 모바일 SDK 범위를 다시 정한다 |

GATT UUID가 기본 프로필과 같으면 `wrappers/ble-profile.json`의 `verified`를 true로 바꾸고
`python tools/sync_binding_metadata.py`로 각 언어 상수를 다시 만든다.
